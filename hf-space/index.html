What this agent does

📦 Shipment intelligence

Ask about any shipment and get a natural-language report with cargo details, temperature history, GPS trace, custody handoffs, verdict and risk — all retrieved from a read-only-guarded SQL Server database.

🚨 Incident investigation

When a temperature excursion occurs (S3 event → SQS → worker → RDS), the agent retrieves the actual incident record and cites the applicable cold-chain SOP corrective-action procedure with a verifiable citation.

🛡️ Enforceable read-only SQL guard

The AI can only query approved FDE_VIEWS views — single SELECT, TOP-capped, no modifications, no base tables, no multi-statement injections. Every query is audited with a correlation ID.

✅ Deterministic answer validation

Every prefetched answer passes a 6-check validator (no tool-call syntax, correct shipment ID, synthetic label present, no credential leakage, no fabricated data). A rejected answer is NEVER returned as success.

Methodology

▸ Deterministic evidence prefetch

The AI does not decide which SQL to run for a recognized shipment question. A deterministic prefetch extracts the shipment ID via regex (UC-\d{6}) and executes 5 fixed, guard-valid queries before the model is called:

QueryViewTypical latency
Shipment recordVW_SHIPMENTS185 ms
Recent telemetry (20 readings)VW_TELEMETRY137 ms
Custody handoffsVW_CUSTODY156 ms
Incident recordsVW_TELEMETRY_INCIDENTS124 ms
Notification stateVW_INCIDENT_NOTIFICATIONS137 ms

This collapses a ReAct multi-turn conversation (≥3 model calls) into one synthesis turn, eliminating tool-selection errors and reducing latency from 1500s+ (timeout) to ~30s.

▸ SQL security model
  • Allowlist enforcement: only approved FDE_VIEWS.VW_* schemas — base tables are physically inaccessible
  • SELECT-only: INSERT/UPDATE/DELETE/DROP/ALTER/EXEC blocked by the guard parser (sqlglot T-SQL AST validation)
  • Row limits: TOP 1–100 mandatory; aggregate-only queries exempt
  • Single statement: multi-statement injection rejected
  • Read-only database identity: the agent uses USR_FDE_RO with SELECT on views only — UPDATE is functionally denied
  • TLS verification: SQL Server connections use ODBC Driver 18 with certificate validation (never disabled)
  • Execution timeout: 10-second cap per query
  • Bounded rejection recovery: repeated failed queries are metered; the agent is instructed to stop querying and answer from evidence already retrieved
▸ Model responsibilities
ModelRoleWhy
z-ai/glm-5.3-flashPrimary ReAct reasoning + tool workflowQualified 14/15, zero API failures, best accuracy record
nvidia/nemotron-3.5-lightning-30b-a3bEvidence-grounded synthesis only (prefetch path)~1s/turn vs GLM 250–400s degraded; tool-selection errors eliminated by prefetch
nvidia/nemotron-3.5-embed-1bSOP document + query embeddings (2048-d)Same NIM endpoint/key; no new credentials

No automatic switching: the synthesis model is a fixed configuration (SYTHESIS_MODEL env), not a runtime fallback. GLM handles all non-prefetched questions.

▸ Answer validation

Every prefetched answer passes a deterministic validator before being returned to the user:

CheckPurpose
No raw tool-call syntaxRejects "query_telemetry_db(…)" text as a "successful" answer
Correct shipment ID presentAnswer must reference the queried shipment
Synthetic-data disclosure"Synthetic" must appear in the answer
No credential leakageRegex scan for API keys, tokens, passwords
No fabricated temperaturesNumerical values must be grounded

A rejected answer returns 502 with the exact failed checks — never the unvalidated text. The incident+SOP path uses a stricter 16-check validator including verbatim SOP citation verification.

▸ Audit architecture

Every request is audited with a stable correlation ID in CloudWatch (90-day retention):

  • agent_request_end — status, duration, model, tool count
  • agent_tool_event — per-tool outcome, guard decision, approved views, rows, error class
  • synthesis_validation_rejected — exact failed checks when the validator rejects
  • auth_failure — 401s with pseudonymous actor

Privacy: no prompts, no model responses, no SQL literals, no tokens — only decisions, shapes and outcomes. Actor is a pseudonymous API-key hash.

System architecture

🌐 Public edge

CloudFront (HTTPS, fail-closed) → ALB (guard header, 403 default) → OAuth2 Proxy + Cognito → Streamlit/LibreChat/Grafana

Unauthenticated requests get 403; the only entry is the Cognito login page. Direct ALB/EC2 access is blocked.

🤖 AI agent

LangGraph orchestrator with 3 tools: query_telemetry_db (guarded SQL), search_compliance_sop (Pinecone), fetch_corridor_conditions (weather).

GLM-5.3-Flash handles general reasoning; Nemotron Lightning handles evidence-grounded synthesis on the deterministic prefetch path.

🗄️ Data layer

RDS SQL Server Express with the unified synthetic dataset (4,020 shipments, 64,120 telemetry rows). Read via FDE_VIEWS only — enforced by grants + SQL guard.

Separate read-only identities: agent (USR_FDE_RO), UI (USR_COLDCHAIN_UI_RO), Grafana (USR_GRAFANA_RO), writer (USR_INCIDENT_WRITER, INSERT-only).

⚡ Event pipeline

S3 (synthetic events) → SQS → worker → RDS incidents → SNS. With DLQ, idempotency (EventId dedup), reconcile loop, CloudWatch alarms.

Full audit: every event has an append-only notification attempt ledger.

📚 SOP retrieval

Pinecone serverless (2048-d, cosine, free tier) with 7 SOP documents (44 vectors). Fixed namespace + access filter from config — user input can never alter them.

Retrieved text is wrapped as untrusted reference material with citation requirements.

📊 Monitoring

6 Grafana dashboards (operations, temp/humidity, logistics, live CloudWatch infra, incidents, AI agent audit) + 8 CloudWatch alarms + structured audit JSON.

CloudWatch Logs with 90-day retention; per-request correlation IDs.

Security layers

  • Edge: CloudFront HTTPS → ALB guard header → OAuth2 Proxy + Cognito (fail-closed)
  • Application: SQL guard (allowlist, SELECT-only, TOP-capped, single-statement, 10s timeout)
  • Database: Read-only views (FDE_VIEWS), TLS verification (never disabled), column-level grants
  • Secrets: AWS Secrets Manager → tmpfs app.env (0600, wiped on reboot, never in images/git)
  • Pinecone: Config-only index/namespace/access filter; API key via hidden prompt → Secrets Manager
  • Audit: Structured JSON, no prompts/responses/SQL-literals/tokens, pseudonymous actor, 90-day retention
  • Answer validation: 6-check general + 16-check incident validators; rejection = 502 with failed checks
